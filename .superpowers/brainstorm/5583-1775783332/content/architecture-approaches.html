Architecture Approach

How should PIN lock + privacy masking integrate into the app?

A

Router-Level Lock + Global State

Recommended

Lock screen injected via GoRouter redirect logic. Privacy masking as a global Riverpod provider that all amount widgets read from.

Pros

  • Follows existing patterns (GoRouter redirects already handle auth)
  • Lock screen is a route — clean back-button handling
  • Single privacy provider — all screens react automatically
  • PIN stored in flutter_secure_storage (encrypted)
  • Biometrics via local_auth package

Cons

  • Router redirect logic gets more complex
  • Need to ensure lock screen can't be skipped via deep links
B

Overlay-Based Lock + Widget Wrapper

Lock screen as a full-screen overlay above the MaterialApp. Each amount widget wrapped in a MaskedAmount widget that checks privacy state.

Pros

  • Lock is independent of routing — no redirect logic changes
  • Overlay can't be bypassed by any route
  • MaskedAmount widget is explicit — clear what's masked

Cons

  • Overlay management is tricky (lifecycle, state restoration)
  • Doesn't follow existing patterns in the app
  • Wrapper widgets add verbosity to every amount display
C

Hybrid — Router Lock + CurrencyFormatter Masking

Lock screen via GoRouter (like A). But instead of wrapper widgets, masking is built directly into CurrencyFormatter — when privacy mode is on, format() returns ****. Zero changes to existing screens.

Pros

  • Lock screen follows existing router patterns
  • Masking is automatic — every amount already goes through CurrencyFormatter
  • No wrapper widgets, no screen-by-screen changes
  • Smallest code footprint by far

Cons

  • CurrencyFormatter becomes context-aware (needs access to provider state)
  • Some amounts might not go through the formatter (edge cases)
